Modeling assumptions & notes

These fictional instructional records illustrate introductory MySQL JOIN concepts. JOIN operations are calculated locally in your browser from the four records in each active source table. No database server is running.

In Employees & Parking Spaces, each table has a unique, non-NULL primary key. PARKING_SPACE.employee_id is a nullable, UNIQUE foreign key: an assigned space references an existing employee, an employee has at most one assigned space, and multiple unassigned spaces may store NULL.

In Customers & Orders, each table has a unique, non-NULL primary key. ORDERS.customer_id is a NOT NULL foreign key referencing an existing customer. A customer may have zero or multiple orders. These are explicit business rules, rather than conclusions drawn only from sample patterns.

Stored NULL means an unassigned parking space in these examples. Outer JOINs can also introduce NULL fields for a missing source row; the result and row trace distinguish those origins. CROSS JOIN produces all combinations without an equality condition and creates no assignments or orders.

Source-table pop-outs show seven fictional illustrative records per table, including additional attributes and records beyond the smaller active JOIN datasets. Those expanded views never enter the active JOIN calculation.
